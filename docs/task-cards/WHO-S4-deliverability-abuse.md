# WHO-S4：退信 / 投诉闭环、抑制、反滥用、域声誉

状态：**待启动 · 依赖 S2**

设计依据：[`docs/product-design.md`](../product-design.md) v1 §4.2、§8.2、§9、§10。

## 背景

能发出邮件不等于能持续发出邮件。自建邮件的最大风险是域声誉、退信放大和滥用。S4 建立可观测的退信/投诉回流、抑制表和滥用刹车，避免少数账户拖垮整个 `tomlab.cn` 域。

## Goal

1. relay 的 DSN / 退信 / 投诉能回流到 Who You，并被结构化记录。
2. 硬退信进入抑制表，后续发送显式拒绝；软退信退避重试。
3. 异常发送行为可自动暂停并告警，处置有人工环节。
4. SPF / DKIM / DMARC 配置可验证，域声誉有监控口径。

## In Scope

- relay → Who You 的内部回调（独立鉴权，不挂 `/mcp`）。
- DSN / ARF 解析与 `DeliveryEvent` 落库。
- `Suppression` 表与 `recipient_suppressed` 错误码。
- 速率、收件域、内容重复度等异常检测与自动暂停。
- 告警：退信率、投诉率、队列积压、异常暂停。
- SPF / DKIM / DMARC 配置验证清单与回归脚本。
- 滥用处置 SOP（人工复核、恢复条件）。

## Out of Scope

- 垃圾邮件过滤产品的完整实现（是否引入第三方网关仍待决）。
- 客户端展示层（S5）。
- 营销邮件、订阅管理。

## 验收证据

1. 构造硬退信 DSN：进入 `DeliveryEvent`，收件人进入抑制表。
2. 对已抑制收件人再次发送：`recipient_suppressed`，无 relay 调用。
3. 构造投诉回流：账户触发暂停，告警可达。
4. 超过速率阈值的发送被拒绝或排队，错误码明确。
5. 外部邮件头显示 SPF / DKIM / DMARC 通过；失败配置能被检查脚本发现。
6. 告警与日志不含地址、主题、正文。

## 依赖与阻塞

- S2 已合入且 relay 可用。
- v1 §10 P0 #8、#9、#12 必须闭环：relay、鉴权、退信/投诉通道。
- DMARC 策略收紧需人工裁决，不得自动从 `p=none` 跳到 `p=reject`。
