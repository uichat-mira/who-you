# WHO-S3：状态、附件、检索质量、保留与导出/删除

状态：**待启动 · 依赖 S1**

负责人：待指派

执行仓库：`uichat-mira/who-you`

设计依据：[`docs/product-design.md`](../product-design.md) v1 §4.3、§6、§8.3、§11。

## 背景

S1 只保证「收到、查到」；S2 保证「确认后能发」。S3 补齐日常使用所需的邮箱状态、附件体验、检索质量与数据生命周期，使邮箱在真实数据量下仍然可用、可清理、可导出。

## Goal

1. 邮箱级 flags（未读 / 星标 / 归档 / 垃圾篓）写入幂等、可恢复。
2. 附件下载链路可验证：短时效、绑定账户、不暴露 R2 直链。
3. 检索在真实数据量下可用；FTS5 不可用时有一致的降级行为。
4. 用户可导出、删除自己的邮件数据，删除可验证。
5. 明确保留策略在代码与任务中的落点。

## In Scope

- `whoyou_mail_flag_set`：幂等、版本 CAS、错误可区分。
- 附件：短时签名下载、大小/类型限制、缺失显式失败。
- 检索：索引字段、排序与游标稳定性；`search_text` 规范化；必要时 FTS5。
- 保留：正文 / 附件 / 原始 MIME / 退信记录 / 审计记录的 TTL 配置化。
- 导出：用户可请求的邮箱导出格式与频率限制。
- 删除：账户注销或用户主动删除的数据路径；R2 先删、D1 后删；幂等重试。
- （可选）消费者处理账本：仅在维护者裁决保留时实现。

## Out of Scope

- 发送与 relay（S2）。
- 退信 / 反滥用策略（S4）。
- 客户端 UI（S5）。
- 跨账户迁移、导入第三方邮箱。

## 验收证据

1. 并发两次相同 flag 写入：结果一致，版本不重复递增。
2. 对已删除/隔离邮件取附件：显式失败，不返回空引用。
3. 在真实量级（由维护者给出目标行数）下，检索与分页游标稳定，不重复/不漏。
4. FTS5 可用/不可用两种环境下行为一致或降级明确。
5. 删除任务可验证：对象与行均消失，重跑幂等；备份残留窗口符合声明的保留策略。
6. 导出文件不包含其他账户数据，且导出行为有审计记录。

## 依赖与阻塞

- S1 合入。
- 保留期、导出格式、删除 SLA 需维护者裁决（v1 §11 #5、#14）。
- 附件链接是否允许转发需裁决（v1 §11 #6）。
